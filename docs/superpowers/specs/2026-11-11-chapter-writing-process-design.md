# 章内正文生成过程卡设计

2026-11-11，用户确认“保留章内入口，升级为完整过程卡”。遵循 DESIGN.md 与已完成的小说/章节工作台。

## 布局与状态

在章节预览内使用独立过程卡，包含任务身份、真实状态、轮次/耗时、五步流程（生成/内容约束/文风/自洽/保存），三项审校结果以分卡与可展开建议承接。只呈现实际消息，不显示估算百分比或虚构 token 流。

启动后立即显示准备态，首个 write-progress 到达后转运行。按当前轮累积分项结果，跨轮保留完整审校报告并标注报告所属轮次，避免旧报告被误读为当前稿结论。保存中不宣称已保存；run_finished 才进入完成态并刷新详情；完成后过程默认收起，优先展示正文，审校记录可随时展开。失败/异常退出显示明确状态与重试入口，保留本次已收到的进度和报告。

## 行为边界

保持章内入口与书库资料切换，过程卡只属于目标章，单例运行时其他章节仅禁用入口。重新生成继续先确认覆盖，并在运行期间保留旧正文阅读；失败不宣称草稿已保存，已有正文保留。失败重试或再次生成替换本次客户端展示历史；离开浏览页仍中止进行中的会话。模型调用、三轮上限、落盘与入库契约不变。

## 模块与验收

正文专属组件、进度状态纯函数和样式放 components/chapter-writing，OutlineNodeCard 负责组装章资料与调用组件，PreviewPane 保留会话宿主职责。按现有接口兼容旧 ChapterWriteProgress 类型引用。
