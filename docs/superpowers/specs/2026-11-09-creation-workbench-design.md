# 新建小说创作工作台设计

日期：2026-11-09。用户已回复“开始”，确认采用方案 A 与本任务包。

## 目标与现状

将新建小说页升级为与书库现代视觉一致的创作工作台，所有流程内容通过卡片展示，保留用户每次输入，并实时展示工具与子 Agent 的执行过程。

当前 `CreationFlow` 将 notify 渲染为文本段落，仅在页面底部显示待答问题；`useAgentSession` 不保存已回答的问题，协议没有工具和 Agent 生命周期消息。完整过程展示需要同时调整 shared 协议、Agent 事件上报和客户端会话状态，属于跨模块复杂需求。

## 方案比较

| 方案 | 视觉与交互 | 权衡 |
| --- | --- | --- |
| A：创作工作台（推荐） | 左侧阶段导航，右侧按时间排列的卡片流；输入、回答、成果、工具、Agent 各有清晰层次 | 兼顾创作阅读与完整过程，需要贯通事件链路 |
| B：单列卡片对话 | 将现有单列内容全面卡片化，顶部保持阶段条 | 更紧凑，但长流程的阶段定位较弱 |
| C：表单向导 + 独立执行日志 | 当前阶段占主区，调用集中到侧栏 | 表单聚焦，但历史回答与执行过程分散 |

以下设计与任务包采用方案 A。

## 页面与视觉

- 固定顶部：返回书库、页面标题与当前状态；副文案说明已确认内容自动保存。
- 左侧约 216px 的阶段导航卡：起步命名、类型、视角、受众、世界观、角色、核心冲突、大纲；当前项高亮，已到达阶段可定位历史内容，未来阶段只展示进度、不跳过业务步骤。
- 右侧自适应主区：阶段标题与简短引导，下方展示按发生顺序排列的活动卡片；充分利用窗口宽度，避免大面积无意义留白。
- 使用项目现有语义色、字体、控件高度和浅暗主题；采用柔和底色、细边框、圆角、轻投影和统一线性图标。状态同时使用文字和图标表达。
- 窄窗口将阶段导航压缩为横向可滚动步骤条，主区单列；长文本和工具参数换行，不引入横向页面滚动。

## 卡片与交互

1. **输入卡**：明确的问题标题、输入类型提示、卡片化选项、统一提交动作。自由文本支持多行与中文输入法；键盘提交规则有提示。每个问题按 request id 独立管理控件状态。
2. **回答卡**：提交后保留问题与本次答案，包括多选、数字、确认/要求修改及可选步骤的跳过；历史内容只读。当前会话内可回看，重新进入恢复流程不承诺完整重放历史交互。
3. **Agent 卡**：展示如“世界观 Agent”“角色 Agent”“大纲 Agent”的名称、任务摘要、运行/等待输入/完成/失败状态与耗时；展开查看输入摘要及输出摘要。
4. **工具卡**：展示面向用户的动作名称及实际工具名、所属 Agent、开始/完成/失败状态、耗时；参数与结果默认折叠，展开后结构化呈现并限制超长内容首次渲染长度。ask_user、保存/确认工具执行期间的用户输入在活动流中自然相邻呈现。
5. **成果卡**：复用 ViewCard 的世界观、角色、冲突、大纲等领域内容，套用一致卡片层次；确认门与对应成果归属于同一个问题，不重复渲染同一成果。
6. **状态卡**：初始化、处理提示、警告和错误均以卡片承载；错误显示继续流程与返回书库动作。

用户停留底部时跟随新内容；向上阅读时不强制滚动，提供回到最新内容入口。当前输入保持容易发现，并保留等待输入状态。快速重复提交只发送一次回答；进程退出时将未完成活动标记中断，避免永久运行中。

原有面向终端的启动 banner、内部 ID 与数据实现说明不直接搬到产品卡片中；CLI 保留既有行为，客户端使用有意义的创作提示。展示执行事件和业务数据，不展示模型隐藏推理或系统提示词。

## 数据流与模块边界

- `packages/shared/src/protocol.ts` 增加结构化活动事件：活动 ID、父活动 ID、Agent/工具类别、名称、状态、时间及可选输入/输出摘要。使用稳定活动 ID 更新已有卡片，工具活动关联所属 Agent，重试时区分不同执行。
- `apps/agent/src/ui/` 提供活动上报出口，ProtocolChannel 发送新消息，CLI/FakeChannel 保持可用；业务层继续遵守 UiChannel 边界。
- `apps/agent/src/agents/react.ts` 在真实调用边界上报 Agent/工具开始、结束和失败；开始事件必须早于工具执行，不能只依赖 step 结束后批量回传，否则等待用户输入时界面无法显示调用。
- `apps/agent/src/workflows/agents/` 向通用运行器提供 Agent 名称和通道，覆盖新建流程的世界观、角色、大纲与自动角色补全调用。事件不得改变确认门、落库和异常传播语义。
- `useAgentSession` 在原会话泵上增加有序活动记录和问题/答案历史；使用独立的活动数据入口，使章节规划与大纲重生成页能够继续消费原 `flow`，避免默认将新增条目误当作 ViewCard。
- `CreationFlow` 负责工作台布局，新卡片组件负责活动与历史展示，输入组件负责交互。新增样式限定于创作工作台，公共成果卡和其他页面保持正常。
- Electron 主进程已有 shared schema 复验与 IPC 转发，验证新事件通过全链路；协议版本按实际兼容规则一致维护。

本次不新增数据库表；新活动与回答历史保存在当前页面会话状态。继续未完成流程复用已有流程缓存，清理上一执行的活动状态，不混淆工具 ID 和请求 ID。

## 验收标准

- 从可选命名到大纲确认，问题与答案按顺序保留；选择、自定义、多选、数字、自由输入与确认/修改路径均可操作。
- 实际触发世界观/角色/大纲/自动补全 Agent，以及 ask_user、查询、保存工具时，可在执行尚未结束时看见运行卡，结束后有对应结果；失败与用户中止不残留假运行状态。
- 每种内容有对应卡片；领域成果仍可完整阅读与确认，状态不因折叠和导航被重置。
- 明暗主题、约 900px 与 1600px 窗口、长中文与长工具参数均布局正常；复验章节规划、大纲重生成与正文生成页。
- 使用可控模型/协议替身做可重复的执行与交互验证；视觉截图来自真实组件。真实线上模型调用若未执行，交付时明确说明该验证边界。
