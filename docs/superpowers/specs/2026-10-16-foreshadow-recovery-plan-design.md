# 伏笔多幕回收规划

状态：用户已要求实施；注意度澄清为沿用原定义（1 易发现、10 难发现），历史分数不变。

## 行为

大纲新增伏笔必须提供埋设幕与至少一个回收幕。允许同幕或后续多幕，禁止更早的幕；难发现的伏笔可拉长跨度，作为提示词节奏指导，不按分数机械指定幕数。模型新输出使用 recoverActNames 数组。

章节 Agent 获得按全书顺序排列的完整当前大纲（部/幕梗概、情节点、已有章名与概述）。先为本幕既有伏笔安排登场和回收，再发现新伏笔。确认前检查既有清单覆盖与真实章节引用，不能默默遗漏既定本幕任务。

章节新增伏笔使用 recoveryPlan: [{ actName, chapterNames }]（至少一项、幕不重复）。本幕回收必须指定本次生成的真实章，已规划的后续幕指定其已有真实章，尚未规划的后续幕 chapterNames 为空，待规划该幕时细化；禁止虚构未来章名。具体回收章严格晚于登场章，同幕种收必须是不同章。

## 持久化与恢复

数据库 22→23 增 edit_revision 编辑计数（普通编辑递增、自动绑定保持）及 recover_act_node_ids JSON 数组，旧单幕转为单元素数组、空为 []；保留旧 singular 字段作为兼容读取，不改注意度。每幕查询只判断该幕是否缺回收章，而非整条伏笔是否已有任意回收章。回收绑定合并所有幕的章 ID，保留已有绑定并去重。

保留主流程缓存幂等步骤。未确认重试刷新本幕两清单，确认时将清单序号映射与产物共同缓存；确认后原空章回收幕已有章时，受限细化 Agent 只选择已有真实回收章，经确认与缓存再入库。已确认旧缓存允许读取旧单幕字段，未确认规划恢复时补齐全书上下文；已经确认的新产物仍先缓存再入库。暂停期间用户编辑的伏笔继续优先保留。逆序规划时，跨幕后续回收可先绑定（按已知埋设幕校验），后续登场章绑定再验证全书章序。

## 写作与展示

确认门和伏笔预览展示完整回收幕/章计划，不能因已有一个回收章而隐藏尚未细化的回收幕。CLI 同步展示。仍有更晚计划回收幕未细化时，当前已绑回收章只能阶段回收，不能提前要求完整真相揭露；写作与审核沿用同源上下文。

## 验收

覆盖：缺回收计划拒绝；同幕与跨部多幕；前置幕/不存在幕/虚构章拒绝；既有任务遗漏重提；新伏笔跨幕计划落库；一幕绑定不影响另一幕待办；多幕追加不覆盖；后幕先规划；旧库迁移与旧缓存；暂停期间编辑；后续幕尚未细化不提前最终揭露；真实 UI 展示。最后运行 typecheck、lint、全量测试及独立审查，代码与两级文档原子提交。
