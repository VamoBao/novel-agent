# 章节规划卡片工作台设计

日期：2026-11-11。用户已确认“按双栏卡片工作台实施”，参照 DESIGN.md 与 CreationFlow。

## 目标与布局

顶部显示返回书库、章节规划标题与真实运行/等待输入/暂停状态。宽窗使用左侧本幕资料与会话导航、右侧有序卡片流；960px 以下将左栏压缩为可展开的本幕资料和横向导航。书名、幕名、梗概、关键情节点来自 App 已加载的详情，无新增查询。

左栏导航为“本幕概要”“当前交互”“章节方案”，只负责定位已存在的内容，不伪造阶段或百分比。右侧欢迎卡说明章节名、剧情概述、登场人物与伏笔将共同规划；所有事件通过既有 timeline 呈现，提问作答后原位保留。

## 交互与复用边界

提取 CreationFlow 的时间流卡片渲染及滚动跟随为可复用单元。两页共用输入、回答、通知、成果与 Agent/工具活动卡；新建小说保留专属阶段卡和导航。章节规划不展示新建小说的八阶段路线。

当前输入使用工作台多行控件，支持输入法、Ctrl/⌘+Enter、数字默认值和确认修改。章节方案继续渲染完整 ViewCard（逐章人物、新角色、地点和伏笔/绑定清单），确认门与协议、入库逻辑保持原契约。只有真实确认并保存后才呈现保存含义。

运行中的工具按 activityId 原位更新，详情折叠状态保留；等待输入关联所属工具与 Agent。翻看历史时不强制滚动或抢焦点，有新内容时提供“回到最新内容”。致命错误保留当前页面历史并显示继续未完成流程，重试按既有 runId 恢复，完成后刷新详情并保持幕选中。

## 验收

真实 React + IPC 替身覆盖启动目标、回答历史、活动等待与完成、方案确认修改、输入法、错误恢复、滚动与导航定位。对 CreationFlow 运行回归。Electron 浅/暗主题、900/1600px 检查准备/输入/方案/异常状态及长文本；补查640px窄窗和横向溢出。全量 typecheck/lint/test 与客户端 build 通过。模型结果用协议替身，不调用线上模型、不写用户小说。
