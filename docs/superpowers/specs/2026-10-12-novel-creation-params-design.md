# 小说创作参数持久化设计

状态：2026-10-12 用户已确认任务包并指示开始。

将类型、受众、核心冲突绑定至 novels 行，逐项收集后立即保存。genre 为可空 TEXT；audience 为可空 JSON 字符串数组（已选标签与补充说明，空数组不同于未采集）；core_conflict 为可空 JSON 对象，复用 coreConflictSchema。历史记录保留 NULL，不推断回填。

数据库版本 15→16，受支持旧版本增量补列，新增三列与版本号在同一 immediate 事务中提交，并在取锁后复查版本防止并发重复迁移；新库直接建目标结构。NovelStore 读写过共享 schema，非法输入在写 SQL 前拒绝，损坏 JSON 报出小说 ID 与字段。普通小说管理操作仅更新明确给定字段，保留创作字段，避免跨进程覆盖。

详情查询 novelDetail.novel 增三项字段，旧载荷缺省为 null；书库列表契约不变。大纲重生成传入所有非 null 的创作字段，旧小说沿用缺省策略。客户端展示编辑、其他写作上下文、确认门、断点恢复与 eval 为后续需求。

验收：新建与部分更新、重开往返、历史库保数据迁移、普通管理保留字段、非法输入零写入、损坏 JSON 可定位、中途停止保留已采集字段、重生成上下文复用；typecheck/lint/全量 test 通过。验证使用临时库，不迁移真实小说库。

方案选择：直接三列（复用小说生命周期与部分更新）优于新增 1:1 表（当前无独立版本化需求）和单个 JSON 列（分阶段写入需要整体合并）。
