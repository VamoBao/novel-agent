# 角色迁移的测试与回归流程

更新时间：2026-10-14。适用于固定角色基准、迁移管理、历史升级及正文上下文的修改。

## 执行顺序

1. 用确定的角色卡、章节位置和操作顺序复现问题。先增加回归测试，确认修复前的实现会失败；记录失败的业务断言。
2. 修复后运行 `bun run test:character-migrations`，同时验证失败路径零副作用和合法操作成功。
3. 提交前运行以下完整检查，不能用定向测试替代全量测试：

```sh
bun run typecheck
bun run lint
bun run test
```

测试依赖经 `bun install --frozen-lockfile` 安装。`happy-dom` 仅用于客户端开发测试，不进入应用运行路径。全量测试包括表单交互测试；无需启动 Electron 或提供模型 API Key。

## 测试隔离与断言要求

- 每个数据库用例使用独立内存库或临时文件库。CLI 子进程明确设置 `NOVEL_DB_PATH`；涉及正文文件时明确设置临时输出目录。不得让测试升级或写入日常书库。
- 表单交互测试使用真实 React hooks 和 DOM 事件，把 IPC 边界接到真实 query/store 与 SQLite。SSR 只验证只读展示，不能单独作为编辑、复制、确认的验收。
- 拒绝操作要比较操作前后的完整记录与快照，而非只断言抛错。取消表单与确认失败应分别验证。成功操作断言 ID、sequence、revision、状态和详情刷新。
- 迁移链测试同时覆盖创建顺序和故事顺序；改变字段、起止章或大纲版本时都要检查前后两条链。不得仅测试从第一条顺序添加到最后一条。
- 陈旧提示用固定时间区分“确认→生成→修改”与“修改→重新生成”，避免靠 sleep 制造时序。快照 `createdAt` 表示修改发生时刻；当前行 `updatedAt` 表示最近修改时刻。
- LLM 替身仅替换外部模型调用，保留上下文组装、修订、文件和数据库行为。用请求载荷验证角色归属与上下文一致性；替身返回合格分数不代表文学效果合格。

## 人工正文验收

在独立测试小说中安排角色“热情→谨慎”的第 4～7 章迁移，检查第 3 章基准、第 4～6 章渐变、第 7 章诱因与转变、第 8 章新状态，再倒序重生成第 3 章。加入另一名同样“热情”但目标不同的角色，检查两条变化不会互换。

确认文学效果时阅读正文及邻章衔接，检查诱因没有被虚构为此前已经发生、角色没有获知作者的结局计划。该项需要真实模型与人工阅读；自动化测试不代替此验收。
